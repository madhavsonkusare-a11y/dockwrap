01

Design-review subagent on Playwright MCP

Highest leverage · your harness already exists

A dedicated review agent that opens the real app in a browser, drives it, screenshots each state and returns triaged findings. The reference implementation is OneRedOak/claude-code-workflows (design-review subagent + /design-review command + CLAUDE.md memory). It is the single biggest upgrade because you already run a preview server on 127.0.0.1:4173 and already have Playwright — the agent gets to look instead of guessing from source.

Point it at the preview server rather than a deployed URL, and give it the three viewports your snapshot config already uses so its findings line up with your baselines.

02

Anti-slop / fingerprint audit prompt

Fixes the exact complaint that started this project

Your original brief was "it looks generic with no identity." That is a named, checkable failure class now. awesome-claude-design catalogues the default fingerprints agents fall into (teal accents, blinking status dots, left-accent bars on every card, three-column feature grids, container nesting soup, Inter-everywhere) and ships a break-default-aesthetic.md counter-prompt plus an audit-live-site scored punch-list. Anthropic's own frontend-design skill bans overused fonts before code is written.

Run this against every new screen. It is cheap, needs no tooling, and catches regressions toward the mean — which is what happened to the original Local Store UI.

FREEPROMPT PACKNO TOOLING
Audit this screen for generic-AI-design fingerprints.
For each of: font choice, accent colour, card treatment, radius
discipline, icon set, layout rhythm, copy voice — say whether it
could appear unchanged in any other product. Quote the CSS line.
Then name the one detail that only this product could have.
03

Dark-mode legibility & contrast gate

Your measured, specific risk

Negative polarity (light text on dark) loses to positive polarity for acuity and proofreading, and the gap widens as type gets smaller. Local Store is dark-only with 75% of its font-size declarations at 12px or below — the worst case in that literature. Automated tools catch roughly 30–40% of WCAG issues, but contrast is squarely inside that 30–40%, so it is worth gating in CI.

You already import AxeBuilder in three specs. Extend rather than add: assert a minimum computed font-size on body text, and fail on any contrast violation instead of only checking the default rule set.

ALREADY INSTALLED@axe-core/playwright 4.13CI GATE
Add to tests/ui/app.spec.js:
new AxeBuilder({page})
  .withTags(['wcag2aa','wcag22aa'])
  .analyze()                      // fail on any violation

Plus a legibility assertion:
every text node rendered on --canvas must compute to
>= 13px, or be a label with letter-spacing >= .08em.
04

Interaction-level critique (UXBench framing)

Right shape for the setup wizard

Most critique prompts judge a static screenshot. UXBench measures whether a critique is actionable, and evaluates critiques produced after browser interaction — treating missing feedback, silent validation, hidden consequences and weak recovery paths as evidence you have to observe by clicking, not by looking.

That is precisely the failure class a setup wizard lives or dies on, and precisely what a screenshot review cannot see. Related agent systems worth reading: PerceptUI (persona-conditioned synthetic users), UXAgent, SimUser.

FREEPROMPT + BROWSERBEST FOR FLOWS
Drive this flow end to end, then report only what you could not
have known from a screenshot:
  1. actions that gave no feedback within 100ms
  2. validation that failed silently
  3. consequences not disclosed before the point of no return
  4. dead ends with no recovery path
  5. state lost on Back
Cite the step number and what you clicked for each finding.
05

Design-token / consistency linter

Would have caught your eleven border-radii

@lapidist/design-lint is design-system-aware: it flags raw values that do not match your configured tokens across CSS, JS and TS, including inline styles. Spacing and radius drift is the classic silent failure — no ordinary linter flags a 13px gap, and no reviewer writes "the rhythm is broken."

Your audit found eleven distinct border-radius values across 28 declarations and sixteen font sizes. A token linter turns that from an occasional manual audit into a build-time error.

FREECLI / CICSS + JS + TS
npx @lapidist/design-lint src/styles src/js
config: radius [0,4,8,999] · space 4/8 scale
        type [12,13.5,15,16.5,21,26,34,42]
        colour: only var(--*) — no raw hex in components

Catalogue · 04

Benchmarks worth reading before you trust a score

UI-Bench

10 tools, 30 prompts, 300 sites, 4,000+ expert pairwise judgments, ranked with a TrueSkill model. Crucially it isolates visual craft — layout, typography, colour, hierarchy — and deliberately ignores accessibility, performance and code quality. Useful as a taste benchmark; do not read it as a UX score. arXiv 2508.20410

UXBench

Measures whether an LLM's critique is actionable, from critiques generated after real browser interaction. Its four evidence classes — missing feedback, silent validation, hidden consequences, weak recovery — are the best ready-made rubric for judging a flow. arXiv 2606.16262

PerceptUI

LLM agents as human-aligned synthetic users for UI/UX evaluation. Related systems: UXAgent (persona-conditioned agents on live targets), SimUser (heuristic issues in mobile apps), UXCascade (aggregating agent traces into findings). arXiv 2606.05697

The honest caveat

Automated accessibility tooling catches an estimated 30–40% of real WCAG violations, and agent critique has no validated correlation with task success. These tools raise the floor and catch regressions. They do not replace watching five self-hosters try to install Memos.

The 30-minute version

Install Playwright MCP, drop the design-review subagent into .claude/agents/, point it at node scripts/preview.mjs on port 4173, and paste the anti-slop prompt from pick 02 into your CLAUDE.md so every future UI change gets audited for genericness by default.
